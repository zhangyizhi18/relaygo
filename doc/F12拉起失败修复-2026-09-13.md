# F12 拉不起交易模块 + 看门狗不生效 · 修复说明

日期：2026-09-13
范围：执行端（`executor/`），仅影响「行情主程序 + F12」启动模式（`THS_LAUNCH_MODE=main_f12`）

---

## 一、你反馈的现象

> 执行端在行情程序还没完全启动就发送 F12，有时候拉起下单程序失败，
> 而看门狗也没起作用进行错误处理。

## 二、根因（三条，逐条对上现象）

**1. F12 发得太早 —— 只判"窗口存在"，不判"窗口可用"**

原实现是：枚举 `hexin.exe` 的顶层窗口，**拿到第一个（面积最大）就立刻发 F12**。
但 hexin 冷启动是分阶段的：先出闪屏 / 登录框，主窗口句柄随后还会变。
在那一刻发 F12，等于发给一个即将销毁的窗口 —— F12 就这么丢了。
外面看起来就是"行情软件明明起来了，就是拉不出下单程序"。

**2. 重试时用的是"同一个旧句柄"，且次数/时窗都不够**

原重试循环 3 次 × 20 秒，且**句柄只在循环外取一次**。
窗口已经从闪屏换成主窗、旧句柄已失效时，3 次重试全打在空气上，60 秒后判失败。

**3. 这条失败路径根本不告诉看门狗 —— 看门狗等于"瞎的"**

看门狗（`ths_watchdog`）只统计**界面级异常上报**。而"启动/拉不起交易模块"这条
路径**一次都没上报过**，所以无论失败多少次，看门狗都不会触发重启。
另外即使触发了，「重启同花顺」在 main_f12 下只关交易模块、不碰行情主程序 ——
而行情主程序自身卡住时，只重发 F12 是白费力气。

---

## 三、改了什么

### 1) 新增「主窗口就绪门槛」（发 F12 前）

窗口必须**同时满足**四条才允许发 F12（`_wait_main_window`）：

| 判据 | 实现 | 为什么 |
|---|---|---|
| 可见、未最小化 | `IsWindowVisible` / `IsIconic` | 最小化状态收不到 F12 |
| 面积 ≥ `THS_MAIN_MIN_AREA`(默认 120000 px²) | `GetWindowRect` 算面积 | 滤掉闪屏、小提示窗 |
| 消息循环有响应 | `SendMessageTimeout(WM_NULL)` 800ms 超时 | 主框架画出来了但还没开始处理消息的"半启动"状态，`IsHungAppWindow` 要等约 5 秒才认，用消息探测更早更准 |
| 尺寸连续稳定 N 次采样 | 默认 3 次（约 1.5 秒） | 布局还在切换/重画时不算就绪 |

### 2) 每一轮重试都重新定位窗口 + 校验 F12 真的发出去了

- **每轮重新枚举行情主窗口**：闪屏 → 登录窗 → 主窗，句柄变了也能自愈；
- `_send_f12` 置前后**复核前台窗口**：只有确认焦点在行情主窗口上才注入按键，
  否则判本次失败、下轮换新句柄重试（顺带避免 F12 被误打进别的程序）；
- 上限从 3 次提到 `THS_F12_RETRY=6` 次，单次等 20 秒，总时长上限
  `THS_F12_TOTAL_WAIT=150` 秒（覆盖冷启动 + 登录较慢的机器）。

### 3) 启动失败上报看门狗 + 升级为「深度恢复」

- 失败时上报 `launch_fail`（路径不存在/启动进程失败）或 `f12_launch_fail`
  （F12 发满仍无交易窗口），**每次启动失败只报一次**；
- 连续 3 次（`THS_WATCHDOG_CONSECUTIVE`）→ 看门狗触发重启；
- 控制台「重启同花顺」/ 看门狗在 main_f12 下若"重发 F12 拉不起来"，自动
  **升级为深度恢复**：连行情主程序一起结束并重启，再按就绪门槛走一遍
  （`_launch_main(force_restart_main=True)`）；
- 常规连接自愈（`ensure_started`）**不会**深度恢复 —— 不能把你正常开着的行情软件反复杀掉。

### 4) 新增配置项（都可留空用默认值）

| 配置项 | 默认 | 含义 |
|---|---|---|
| `EXECUTOR_THS_MAIN_MIN_AREA` | 120000 | 视为行情主窗口的最小面积(px²) |
| `EXECUTOR_THS_MAIN_READY_STABLE` | 3 | 尺寸连续稳定几次采样才算就绪 |
| `EXECUTOR_THS_F12_RETRY` | 6（原 3） | F12 最多重发次数 |
| `EXECUTOR_THS_F12_TOTAL_WAIT` | 150 | 反复发 F12 的总时长上限(秒) |
| `EXECUTOR_THS_F12_PER_WAIT` | 20 | 每次 F12 后等交易窗口出现的时长(秒) |
| `EXECUTOR_THS_MAIN_EXIT_WAIT` | 15 | 深度恢复时等行情主程序真正退出的时长(秒) |

## 五、注意与遗留

1. `GetForegroundWindow()` 返回 0 时（锁屏 / 远程桌面断开 / 会话无活动桌面）**放行**发送 F12，
   而不是拒绝 —— 否则锁屏时永远发不出 F12。真机测试仍须保持桌面会话活跃。
2. 看门狗「每小时最多自动重启 N 次」上限不变（`THS_WATCHDOG_MAX_PER_HOUR=3`）。
   若行情主程序路径配错，会最多重启 3 次后转为只告警 —— 这是刻意的（防重启风暴）。
3. **本次修复未发版、未推 .252**。要让常驻执行端生效需重启执行端；正式落地走发版流程。
