【exe 使用方法 · 中转服务】
1. 把 jq-relay-v1.3.0-20260911-1617-win64.exe 放到单独目录。
2. 先进 cmd 设好密钥再启动（不要直接双击）：
   set RELAY_SIGNAL_KEY=你的聚宽密钥
   set RELAY_EXECUTOR_KEY=你的执行端密钥
   set RELAY_WEB_SECRET=一段随机字符串
   set RELAY_WEB_ADMIN_PASSWORD=你的控制台管理员密码
   jq-relay-v1.3.0-20260911-1617-win64.exe
3. 验证:
   - 服务:   浏览器打开 http://127.0.0.1:5010/api/status ，看到 "version":"v1.3.0" 即成功
   - 控制台: 浏览器打开 http://127.0.0.1:5010/console/ ，能打开登录页即成功
4. 防火墙放行 5010 端口（聚宽云端与控制台都要能连进来）。

【exe 使用方法 · 执行端】（跑在有同花顺/miniQMT 的 Windows 上）
1. 把 jq-executor-v1.3.0-20260911-1617-win64.exe 放到执行端机器任意目录。
2. 设环境变量后双击运行:
   set EXECUTOR_MODE=dry_run          （先用模拟模式验证；真实下单改 ths）
   set EXECUTOR_RELAY_URL=http://中转服务IP:5010
   set EXECUTOR_API_KEY=与中转服务 RELAY_EXECUTOR_KEY 完全一致
   jq-executor-v1.3.0-20260911-1617-win64.exe
3. 依赖自检（可选）:
   set EXECUTOR_SELFCHECK=1
   jq-executor-v1.3.0-20260911-1617-win64.exe
   打印 SELFCHECK_OK version=v1.3.0 mode=... 即依赖完整。
4. 日志 executor.log 生成在 exe 同目录。

【Docker 使用方法】
   解压 jq-relay-docker-v1.3.0-20260911-1617.zip
   cd jq-relay-docker-v1.3.0-20260911-1617
   （先改 docker-compose.yml 里 environment 段的 4 个密钥）
   docker compose up -d --build
   数据落在 named volume jq-relay-data，容器重建不丢。

【常见问题 FAQ】
Q: 双击 exe 窗口一闪就没？
A: 在 cmd 里运行它看报错。最常见是 5010 端口被占用（netstat -ano | findstr 5010）。
Q: 升级后密钥/数据还在吗？
A: 数据在 exe 旁边的 relay_data.db，换新 exe 不动它即可；新版会自动补建控制台的表，旧数据不受影响。
Q: 控制台查不到账户信息 / 下单提示执行端离线？
A: 控制台只负责下发指令，必须有一台开着同花顺/miniQMT 的 Windows 机器跑着执行端
   且心跳正常。请先在执行端所在机器启动执行端。
Q: 忘了控制台管理员密码？
A: 停掉服务，备份后删掉 relay_data.db（或只删 users 表）再重启，会用配置里的默认管理员重建。
Q: 升级后页面还是旧样子？
A: 99% 是浏览器缓存，Ctrl+F5 强制刷新；Docker 版强刷无效说明镜像没重建（up -d --build）。
Q: 执行端 exe 报缺模块/缺模型？
A: 用 EXECUTOR_SELFCHECK=1 自检定位；请用官方发布的 exe，不要自行用别的环境打包。
Q: exe 报毒/被杀软拦截？
A: PyInstaller 单文件常见误报，加入白名单或改用源码方式运行。
