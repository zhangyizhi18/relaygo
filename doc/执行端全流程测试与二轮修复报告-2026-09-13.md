## 一、用户反馈的两个现象

> 「重启执行端后能启动行情，还是无法拉起下单程序，看门狗也没起作用」

一轮修复（commit 见 git log）只解决了"窗口存在即算就绪""句柄乱变打空""失败不上报看门狗"三处，但真机冷启动仍会失败，且看门狗仍不触发。本轮在真机追到**两个更深的根因**：

1. **F12 误发到「登录框」而不是「行情主框架」**
   同花顺冷启动先出 `class=#32770 title='登录到全部行情主站'` 的登录框，行情主框架（`class=Afx:004A0000:...`）要十几秒后才出现。一轮修复的就绪门槛只认 `Afx:` 前缀，但 `_wait_main_window` 取窗口时仍可能把登录框当成"主窗口"，于是对登录框发了 F12 → xiadan 被拉起后立刻自退（实测 19:27:05→19:27:08 起→19:27:11 退，白等 60 秒）。
2. **等待循环盲目等满 60 秒，不重发 F12**
   `ensure_started` 的等待循环只在开头取一次行情窗口句柄，之后死等 `THS_AUTOSTART_TIMEOUT`（60s）。一旦刚出现的交易窗口自退，循环不会感知，也不会重发 F12，直到 60 秒超时。

叠加这两点，冷启动首轮几乎必败，且失败路径仍没把 `launch_fail` 报给看门狗（main 循环还会因中转不可达而短路，连 `ensure_broker_ready`/看门狗都不跑）。

## 二、本轮代码修复（executor/broker_ths.py 为主）

| # | 修复点 | 关键改动 |
|---|--------|----------|
| 1 | **主框架识别** | 新增 `_looks_like_main_frame`：排除 `#32770` 对话框类、排除标题含「登录/提示/注册/Menu/划词/资讯中心」的窗口；`_wait_main_window`/`_pick_main_window` 设 `main_frame_only=True`，**只认真正的行情主框架**（登录框/闪屏一律不算就绪）。 |
| 2 | **交易窗口「真起来」判定** | 新增 `_confirm_trading_window`：要求窗口**连续稳定 N 次采样 + 消息循环有响应**（`_window_responds` 用 `SendMessageTimeout(WM_NULL)`），杜绝"闪现即报成功"的假成功。 |
| 3 | **交易窗口自退即重发 F12** | `ensure_started` 等待循环改为：每轮重新定位行情主窗口 → 若行情主框架就绪但交易窗口不在/已消失 → 立即 `_relaunch_trading_module`（重发 F12），间隔 `THS_RESEND_F12_GAP`（默认 3s），不再盲目等满 60s。 |
| 4 | **看门狗真正联动** | `main.py` 主循环：中转不可达**不再短路**券商自愈与看门狗；`ensure_started` 结束把失败按 `launch_fail`（窗口超时）/ `window_hung`（假死）报给 `ths_watchdog.report_ui_error`，成功则 `_ui_ok()` 清零。连续 3 次 → `should_restart()` 为真 → 自动重启。 |
| 5 | **卖出持仓校验 bug** | `risk.py` 新增 `_held_amount`，兼容中文 `可用余额`/英文 `amount`/T+1 等字段；原 `p.get("amount")` 在中文持仓行恒为空导致**所有卖单被误拒**。13/13 单测通过。 |

新增/调整配置（`executor/config.py`）：`THS_MAIN_MIN_AREA`、`THS_MAIN_READY_STABLE`、`THS_RESEND_F12_GAP`、`THS_F12_PER_WAIT`、`THS_F12_TOTAL_WAIT`、`THS_MAIN_EXIT_WAIT`。
