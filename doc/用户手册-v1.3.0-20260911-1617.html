1. 产品简介与工作原理

本系统解决一个具体问题：让跑在聚宽云端的策略，能够把你本机券商客户端（同花顺 / miniQMT）里的真实账户下出去单。

聚宽云端跑在互联网上，够不着你本机的券商客户端；券商客户端又必须在你的 Windows 桌面上运行。于是在中间加一层 中转服务，把两者连起来：

聚宽云端策略
      │  POST /api/signal   （X-API-Key 鉴权）
      ▼
中转服务（Flask + SQLite，可跑在云服务器 / Docker / exe）
      │  POST /api/signal/poll   ← 执行端主动来拉
      ▼
执行端（跑在有券商客户端的 Windows 机器上）
      │  easytrader / xtquant
      ▼
同花顺客户端 / miniQMT  →  券商  →  成交

核心设计要点：

  • 中转服务不碰券商，只做"信号落库 + 排队 + 回报"，所以极其稳定，可 7×24 跑在云端。
  • 执行端主动拉取（轮询），不用公网暴露 Windows 机器，也不需要端口映射。
  • 所有下单都必须过执行端风控（executor/risk.py），无论是聚宽策略信号还是控制台手工下单。
  • 信号幂等去重：同一个 order_id 重复上报不会重复下单。

2. 系统架构与组件

组件位置职责能否容器化
中转服务 relay_server云服务器 / NAS接收信号、落库排队、Web 控制台、下发任务、收回报✅ Docker / exe
执行端 executor有券商客户端的 Windows轮询信号与任务、风控、调用券商、回报结果❌ 必须 Windows 桌面
聚宽策略 joinquant/jq_signal.py聚宽云端把策略下单意图 POST 给中转服务—
Web 控制台浏览器人工下单/查询/用户/审计（内置于中转服务）—
为什么执行端不能 Docker 化 同花顺客户端 UI 自动化与 miniQMT 都需要真实 Windows 桌面（GUI 窗口、剪贴板、前台锁），Docker 里没有桌面，无法运行。

3. 三种下单方案怎么选

在 executor/config.py 里改 MODE 即可一键切换（也可用环境变量 EXECUTOR_MODE）：

MODE方案适用场景前置条件推荐度
dry_run模拟先跑通全链路，绝不下真单无入门必用
thsA. 同花顺客户端 UI 自动化已有同花顺下单客户端；无需额外权限装 easytrader；同花顺登录并关闭自动升级易上手
thsautoB. 安卓模拟器同花顺 APP 方案雷电模拟器 + 同花顺 APP + thsauto 服务较绕
miniqmtC. QMT 官方接口生产环境（稳定、有官方通道）券商开通 QMT/miniQMT 权限★ 最推荐
合规提示 程序化交易需符合券商与监管要求，实盘前请向券商报备。生产环境优先选 C（miniQMT 官方接口），A（UI 自动化）仅作为兼容手段。

4. 快速开始（三条路径）

路径一：只想快速体验（10 分钟）

1
解压运行中转服务 exe，浏览器打开控制台，用 admin / admin123 登录。
2
在另一台/同一台机器运行执行端 exe，模式选 dry_run。
3
控制台「概览」看到执行端在线 → 「账户查询」能看到模拟资金 → 链路通了。

路径二：跑真实同花顺下单

1
部署中转服务（exe 或 Docker），配置好密钥。
2
Windows 上登录同花顺下单客户端，运行执行端，EXECUTOR_MODE=ths。
3
先用控制台「手动下单」下 100 股小单验证，确认无误后再接聚宽策略。

路径三：生产环境（推荐）

1
中转服务用 Docker 跑在云服务器，密钥改掉，控制台改密码。
2
执行端用 miniqmt 模式，用 NSSM/任务计划注册为开机自启。
3
聚宽策略接入 jq_signal.py，并把风控阈值调到合适值。

5. 中转服务部署 · exe 版

5.1 安装

  1. 把 jq-relay-v1.3.0-20260911-1617-win64.exe 放到一个单独目录（如 D:\jq-relay\）。
  2. 双击运行。首次运行会在同目录生成数据库 relay_data.db。
  3. 默认监听 5010 端口。防火墙需放行该端口（云服务器还要在安全组放行）。
建议：不要双击，先设好密钥再启动 双击用的是默认密钥，正式使用前先在 cmd 里设置环境变量，或用部署脚本启动。

5.2 启动并设置密钥

rem 在本目录打开 cmd，逐行执行（按需改值）
set RELAY_SIGNAL_KEY=你的聚宽密钥
set RELAY_EXECUTOR_KEY=你的执行端密钥
set RELAY_WEB_SECRET=一段随机字符串
set RELAY_WEB_ADMIN_PASSWORD=你的控制台管理员密码
jq-relay-v1.3.0-20260911-1617-win64.exe

5.3 验证

rem 服务健康检查（应看到 "version":"v1.3.0"）
curl http://127.0.0.1:5010/api/status

rem 浏览器打开控制台登录页
start http://127.0.0.1:5010/console/

5.4 注册为开机自启服务（可选）

推荐用 NSSM 或 Windows 任务计划程序，把 exe 注册为后台服务，环境变量写进服务配置。也可用「任务计划程序」→ 创建任务 → 触发器"计算机启动时"。

7. 执行端部署

7.1 方式一：exe 版（推荐给最终用户）

rem 把 jq-executor-v1.3.0-20260911-1617-win64.exe 放到执行端机器任意目录
set EXECUTOR_MODE=ths
set EXECUTOR_RELAY_URL=http://中转服务IP:5010
set EXECUTOR_API_KEY=与中转服务的 RELAY_EXECUTOR_KEY 完全一致
jq-executor-v1.3.0-20260911-1617-win64.exe

日志 executor.log 生成在 exe 同目录。启动后可自检依赖是否完整：

set EXECUTOR_SELFCHECK=1
jq-executor-v1.3.0-20260911-1617-win64.exe
rem 打印 SELFCHECK_OK version=v1.3.0 mode=... 即依赖完整

7.2 方式二：源码 + 一键启动 bat

项目根目录的 启动执行端.bat 会自动建虚拟环境、装依赖、并让你选模式（1=dry_run / 2=ths）。首次运行需几分钟。

必须的依赖顺序 easytrader 内部锁定 pywinauto==0.6.6，但 0.6.6 在 64 位 Python 上有批量 SendInput bug，必须再单独 pip install pywinauto==0.6.8。bat 已自动处理，手动安装时不要漏。

7.3 三种方案的具体配置

A. 同花顺（MODE=ths）

  • 登录同花顺下单客户端（xiadan.exe），并关闭自动升级。
  • executor/config.py 的 THS_XIADAN_PATH 指向 xiadan.exe 完整路径。
  • 需要 easytrader、ddddocr（验证码识别）、pywinauto==0.6.8。

B. 安卓模拟器（MODE=thsauto）

  • 雷电模拟器安装同花顺 APP，启动 thsauto 服务：thsauto run --host=0.0.0.0 --port=5001。
  • 填 THSAUTO_URL、THSAUTO_ADDR（adb 地址，一般 emulator-5554）。

C. miniQMT（MODE=miniqmt，最推荐）

  • 券商开通 QMT/miniQMT 权限，登录 miniQMT 客户端。
  • 填 QMT_PATH（userdata_mini 目录）、QMT_ACCOUNT_ID（资金账号）。
  • 把 QMT 目录里的 xtquant 文件夹复制到执行端目录。

8. 聚宽策略端接入

在聚宽策略里引入 joinquant/jq_signal.py，把下单意图上报给中转服务。要点：

  1. 把 RELAY_URL 改成你的中转服务公网地址。
  2. 把 API_KEY 改成与 RELAY_SIGNAL_KEY 一致的值。
  3. 每个信号必须有全局唯一的 order_id（建议用 策略名+股票+日期+序号），中转服务靠它幂等去重。
# 策略下单处调用（示意）
send_signal(order_id="myStrat-20260911-001",
            security="600519.XSHG", side="buy", amount=100, price=None)
字段必填说明
order_id✅唯一标识，用于幂等去重
security✅聚宽代码，如 600519.XSHG / 000001.XSHE
side✅buy 或 sell
amount✅股数（正整数）
price—委托价；留空/0 时执行端自动取最新价（A 股客户端只支持限价）

9. Web 控制台使用手册

浏览器打开 http://<中转服务IP>:5010/console/（本机为 http://127.0.0.1:5010/console/）。

首次登录后请立即改密码 默认账号 admin / admin123。右上角可修改自己的密码。公网部署务必设置 RELAY_WEB_SECRET。

9.2 概览

显示中转服务版本、执行端在线状态与最后心跳、信号统计、任务统计、最近信号。下单前先确认执行端在线。

9.3 账户查询

四类实时查询：资金、持仓、当日委托、当日成交。查询会下发任务给执行端并向券商客户端实时读取，通常 1～5 秒返回。

查询为空或被弹窗拦截 若同花顺弹出验证码/对话框，可能导致本次读取失败，重试即可；执行端有自动识别与人工兜底机制（见第 11 节）。

9.4 手动下单与撤单

  1. 填写证券代码（600519.XSHG 格式）、方向（买/卖）、数量（股）、价格（可留空=最新价）。
  2. 点「下单」。控制台把任务下发给执行端，同步等待回报后显示委托号与结果。
  3. 撤单：在「当日委托」里找到委托号，填进撤单框点「撤单」。
防重复下单 同一证券+方向+数量在 15 秒内重复提交会被拦截（HTTP 429），避免手抖点两次。

9.5 任务队列

记录每一次操作的执行记录与结果（含状态：pending/running/done/failed/timeout）。排查问题时先看这里。

9.6 用户管理（管理员）

新建用户、改角色、禁用/启用、重置密码、删除。系统强制保留至少一个启用状态的管理员，且不能删除当前登录账号。

9.7 审计日志（管理员）

记录：谁、何时、从哪个 IP、做了什么、结果如何。覆盖登录、登录失败、查询、下单、撤单、用户增删改、权限拒绝等。可按用户名/动作/关键字筛选。

10. 风控机制

所有下单（聚宽信号 + 控制台手工）都经过 executor/risk.py，任一项不通过即拒绝并回报原因：

检查项参数（executor/config.py）默认
代码白名单CODE_WHITELIST空=不限制
单笔最大股数MAX_SINGLE_AMOUNT10000
当日累计上限MAX_DAILY_AMOUNT50000
价格偏差MAX_PRICE_DEVIATION3%
卖出持仓校验自动查询实际持仓持仓不足即拒
实盘前务必按自己的资金规模调整阈值 默认值偏保守。放宽容错意味着放大风险，请谨慎设置。

11. 同花顺验证码处理

同花顺会检测频繁自动操作并弹验证码窗口（反机器人机制，无法根除）。本系统用三级降级把影响降到最低：

1
自动识别（主力）：ddddocr 深度学习 OCR 识别验证码 → 自动填入 → 回车，最多重试 5 轮。
2
人工兜底：连续失败时蜂鸣报警 3 声 + 存图 captcha_last.png，90 秒内人工输入也认，检测到填好会自动回车。
3
最后手段：点取消关闭弹窗，操作如实报 failed，绝不带病重试。

每处理一次验证码，执行端自动降频 120 秒，减少再次触发。可单独自测：python executor/captcha.py（只检测弹窗，不做任何交易）。

12. 常见问题 FAQ

问题原因 / 解决
双击 exe 窗口一闪就没在 cmd 里运行看报错。最常见是 5010 端口被占用：netstat -ano | findstr 5010
控制台提示执行端离线执行端没启动，或执行端 EXECUTOR_RELAY_URL 指向不对，或 EXECUTOR_API_KEY 与中转 RELAY_EXECUTOR_KEY 不一致。
聚宽上报信号返回 401聚宽端 API_KEY 与中转 RELAY_SIGNAL_KEY 不一致。
查询不到账户/持仓同花顺弹窗拦截读取，重试；或客户端未登录。
升级后页面还是旧样子99% 是浏览器缓存，Ctrl+F5 强制刷新。Docker 强刷无效说明镜像没重建，需 up -d --build。
Docker 只执行 up -d 不生效源码改了必须 build 再 up -d。
忘了控制台管理员密码停服务，备份后删 relay_data.db（或只删 users 表）再重启，会按配置重建默认管理员。
exe 被杀软拦截/报毒PyInstaller 单文件常见误报，加入白名单；或改用源码方式运行。
同花顺下单偶发失败客户端弹窗/升级导致控件失效；锁版本、关自动升级。失败会自动回报 failed。
执行端 exe 启动报缺模块用 EXECUTOR_SELFCHECK=1 自检；若缺模型文件，请用官方发布的 exe 而非自行打包。

13. 发布与升级约定

14. 合规与风险提示

  • 本系统是自建中转工具，不构成任何投资建议，不对交易盈亏负责。
  • 程序化交易须遵守所在券商与监管机构的要求，实盘前请向券商报备。
  • 同花顺 UI 自动化属于非官方通道，客户端升级可能导致失效；生产环境建议使用 miniQMT 官方接口。
  • 请妥善保管密钥（RELAY_SIGNAL_KEY/RELAY_EXECUTOR_KEY/管理员密码），公网部署务必修改默认值。
  • 风控阈值、白名单等参数请按自身风险承受能力设置。
