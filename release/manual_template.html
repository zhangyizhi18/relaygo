1. 产品简介与工作原理

本系统解决一个具体问题：让跑在聚宽云端的策略，能够把你本机券商客户端（同花顺 / miniQMT）里的真实账户下出去单。

聚宽云端跑在互联网上，够不着你本机的券商客户端；券商客户端又必须在你的 Windows 桌面上运行。于是在中间加一层 中转服务，把两者连起来：

聚宽云端策略
      │  POST /api/signal   （X-API-Key 鉴权）
      ▼
中转服务（Flask + SQLite，可跑在云服务器 / Docker / exe）
      │  POST /api/signal/poll   ← 执行端主动来拉
      ▼
执行端（跑在有券商客户端的 Windows 机器上）
      │  easytrader / xtquant
      ▼
同花顺客户端 / miniQMT  →  券商  →  成交

核心设计要点：

  • 中转服务不碰券商，只做"信号落库 + 排队 + 回报"，所以极其稳定，可 7×24 跑在云端。
  • 执行端主动拉取（轮询），不用公网暴露 Windows 机器，也不需要端口映射。
  • 所有下单都必须过执行端风控（executor/risk.py），无论是聚宽策略信号还是控制台手工下单。
  • 信号幂等去重：同一个 order_id 重复上报不会重复下单。

组件位置职责能否容器化

为什么执行端不能 Docker 化 同花顺客户端 UI 自动化与 miniQMT 都需要真实 Windows 桌面（GUI 窗口、剪贴板、前台锁），Docker 里没有桌面，无法运行。

3. 三种下单方案怎么选

在 executor/config.py 里改 MODE 即可一键切换（也可用环境变量 EXECUTOR_MODE）：

MODE方案适用场景前置条件推荐度
dry_run模拟先跑通全链路，绝不下真单无入门必用
thsA. 同花顺客户端 UI 自动化已有同花顺下单客户端；无需额外权限装 easytrader；同花顺登录并关闭自动升级易上手
thsautoB. 安卓模拟器同花顺 APP 方案雷电模拟器 + 同花顺 APP + thsauto 服务较绕
miniqmtC. QMT 官方接口生产环境（稳定、有官方通道）券商开通 QMT/miniQMT 权限★ 最推荐
合规提示 程序化交易需符合券商与监管要求，实盘前请向券商报备。生产环境优先选 C（miniQMT 官方接口），A（UI 自动化）仅作为兼容手段。

4. 快速开始（三条路径）

路径一：只想快速体验（10 分钟）

1
解压运行中转服务 exe，浏览器打开控制台，用 admin / admin123 登录。
2
在另一台/同一台机器运行执行端 exe，模式选 dry_run。
3
控制台「概览」看到执行端在线 → 「账户查询」能看到模拟资金 → 链路通了。

路径二：跑真实同花顺下单

1
部署中转服务（exe 或 Docker），配置好密钥。
2
Windows 上登录同花顺下单客户端，运行执行端，EXECUTOR_MODE=ths。
3
先用控制台「手动下单」下 100 股小单验证，确认无误后再接聚宽策略。

路径三：生产环境（推荐）

1
中转服务用 Docker 跑在云服务器，密钥改掉，控制台改密码。
2
执行端用 miniqmt 模式，用 NSSM/任务计划注册为开机自启。
3
聚宽策略接入 jq_signal.py，并把风控阈值调到合适值。

5. 中转服务部署 · exe 版

5.1 安装

  1. 把 relaygo-relay-{{VER}}-{{TS}}-win64.exe 放到一个单独目录（如 D:\relaygo-relay\）。
  2. 双击运行。首次运行会在同目录生成数据库 relay_data.db。
  3. 默认监听 5010 端口。防火墙需放行该端口（云服务器还要在安全组放行）。
建议：不要双击，先设好密钥再启动 双击用的是默认密钥，正式使用前先在 cmd 里设置环境变量，或用部署脚本启动。

5.2 启动并设置密钥

rem 在本目录打开 cmd，逐行执行（按需改值）
set RELAY_SIGNAL_KEY=你的聚宽密钥
set RELAY_EXECUTOR_KEY=你的执行端密钥
set RELAY_WEB_SECRET=一段随机字符串
set RELAY_WEB_ADMIN_PASSWORD=你的控制台管理员密码
relaygo-relay-{{VER}}-{{TS}}-win64.exe

5.3 验证

rem 服务健康检查（应看到 "version":"{{VER}}"）
curl http://127.0.0.1:5010/api/status

rem 浏览器打开控制台登录页
start http://127.0.0.1:5010/console/

5.4 授权激活（{{VER}} 起正式版必须）

正式版中转服务内置卡密授权：服务照常启动，但未激活时除激活页外全部功能被拦截——浏览器打开控制台会自动跳到「授权激活」页。

  1. 打开 http://<IP>:5010/console/，自动进入激活页，页面显示 8 位「本机授权账号」（由机器码自动生成，固定不可修改）。
  2. 把该账号发给管理员，在授权服务端生成卡密。
  3. 把卡密粘贴进激活页的「卡密」框，点「激活」。成功后自动进入控制台，无需重启。
  4. 登录控制台后，顶栏会常驻绿色徽章「授权：剩余 X 天 · 到期时间」（永久卡显示「永久有效」）。
授权服务器临时失联怎么办 授权服务器联系不上时，凭本地缓存进入 72 小时离线宽限期（顶栏徽章橙色提示"离线宽限中"），宽限期内一切功能正常；明确无效（未激活/已过期/被禁用）则会立即拦截。恢复连接后自动回到正常状态。
正式版锁死授权开关 正式发布的 exe / docker 包内置 release.lock，环境变量 RELAY_LICENSE_ENABLED=0 在正式版中一律无效；只有自己拿源码跑的开发环境允许关闭授权。

5.5 注册为开机自启服务（可选）

推荐用 NSSM 或 Windows 任务计划程序，把 exe 注册为后台服务，环境变量写进服务配置。也可用「任务计划程序」→ 创建任务 → 触发器"计算机启动时"。

6. 中转服务部署 · Docker 版

适用于装了 docker + docker compose 的 Linux 服务器（云上推荐）。发布包为 源码包，解压后现场构建，最通用。

6.1 三步启动

unzip relaygo-relay-docker-{{VER}}-{{TS}}.zip
cd relaygo-relay-docker-{{VER}}-{{TS}}

# 第一步：改 docker-compose.yml 里 environment 段的 4 个密钥
#   RELAY_SIGNAL_KEY / RELAY_EXECUTOR_KEY / RELAY_WEB_SECRET / RELAY_WEB_ADMIN_PASSWORD

docker compose up -d --build      # 构建并启动
curl http://127.0.0.1:5010/api/status   # 看到 "version":"{{VER}}" 即成功
Docker 版必须挂载固定 machine-id，否则每次重建容器授权账号都会变 在 docker-compose.yml 的 volumes 段加：- /etc/machine-id:/etc/machine-id:ro， 再 up -d --build。激活方式与 exe 版相同（控制台跳转激活页 → 8 位账号发管理员 → 卡密激活）。

6.2 授权激活（同 exe 版）

激活流程与 5.4 节完全一致：浏览器打开控制台 → 激活页显示 8 位授权账号 → 发管理员换卡密 → 激活。注意先按上面的提示挂载固定 machine-id 再激活。

7. 执行端部署

7.1 方式一：exe 版（推荐给最终用户）

rem 把 relaygo-executor-{{VER}}-{{TS}}-win64.exe 放到执行端机器任意目录
set EXECUTOR_MODE=ths
set EXECUTOR_RELAY_URL=http://中转服务IP:5010
set EXECUTOR_API_KEY=与中转服务的 RELAY_EXECUTOR_KEY 完全一致
relaygo-executor-{{VER}}-{{TS}}-win64.exe

日志 executor.log 生成在 exe 同目录。启动后可自检依赖是否完整：

set EXECUTOR_SELFCHECK=1
relaygo-executor-{{VER}}-{{TS}}-win64.exe
rem 打印 SELFCHECK_OK version={{VER}} mode=... 即依赖完整

7.2 方式二：源码 + 一键启动 bat

项目根目录的 启动执行端.bat 会自动建虚拟环境、装依赖、并让你选模式（1=dry_run / 2=ths）。首次运行需几分钟。

必须的依赖顺序 easytrader 内部锁定 pywinauto==0.6.6，但 0.6.6 在 64 位 Python 上有批量 SendInput bug，必须再单独 pip install pywinauto==0.6.8。bat 已自动处理，手动安装时不要漏。

7.3 三种方案的具体配置

A. 同花顺（MODE=ths）——全程无人值守

  • executor/config.py 的 THS_XIADAN_PATH 指向 xiadan.exe 完整路径（.env 里是 EXECUTOR_THS_XIADAN_PATH）。
  • 自动拉起同花顺：执行端启动时若同花顺未运行会自动启动它（工作目录自动对齐，避免"界面空白/不登录"）；已在运行则绝不重复拉起（EXECUTOR_THS_AUTOSTART，默认开）。
  • 登录阶段无人值守：自动点掉登录界面的「非注册用户」等干扰弹窗（EXECUTOR_THS_AUTODISMISS）；停在登录界面超过 20 秒自动代点[登录]（密码由同花顺自己保存，EXECUTOR_THS_LOGIN_ASSIST）；触发方式可配 altf4,click（EXECUTOR_THS_LOGIN_TRIGGERS）。
  • 绝不误伤同花顺：执行端已整体接管 easytrader 的"关弹窗"逻辑——一个 WM_CLOSE 都不发；同花顺窗口若真的假死（未响应），连接会主动拒绝并提示到控制台点「重启同花顺」。
  • 需要 easytrader、ddddocr（验证码识别）、pywinauto==0.6.8。
  • 建议关闭同花顺的自动升级：升级程序（updater）可能在交易时段杀掉/替换同花顺主程序。

B. 安卓模拟器（MODE=thsauto）

  • 雷电模拟器安装同花顺 APP，启动 thsauto 服务：thsauto run --host=0.0.0.0 --port=5001。
  • 填 THSAUTO_URL、THSAUTO_ADDR（adb 地址，一般 emulator-5554）。

C. miniQMT（MODE=miniqmt，最推荐）

  • 券商开通 QMT/miniQMT 权限，登录 miniQMT 客户端。
  • 填 QMT_PATH（userdata_mini 目录）、QMT_ACCOUNT_ID（资金账号）。
  • 把 QMT 目录里的 xtquant 文件夹复制到执行端目录。

7.5 不用命令行改配置（.env 配置文件）——推荐所有用户用这种

从 {{VER}} 起，完全不需要在命令行里敲 set 或改系统环境变量。程序第一次运行时，会在自己旁边自动生成一份带中文说明的 .env 配置文件，改它就行：

第 1 步：双击程序目录里的 「执行端-配置.bat」（中转服务对应「中转服务-配置.bat」）。
第 2 步：选 1（问答式配置），跟着提示填 3 项必改内容：中转服务地址、执行端密钥、同花顺 xiadan.exe 路径。也可以选 2 用记事本直接打开 .env 手改。
第 3 步：保存后重新启动程序，启动画面会打印配置摘要（每一项生效值 + 来源 + 密钥脱敏显示），确认自己改的配置真的生效了。

.env 的三档优先级：系统环境变量 > .env 文件 > 程序默认值。也就是说 .env 只补"系统里还没设置"的项，用 bat/命令设过的值不会被它覆盖——正常用户只用 .env，完全感觉不到这个规则的存在。

特性说明
自动生成首次运行程序自动在 exe 旁生成 .env，带完整中文注释；已存在则绝不覆盖（升级安全）
记事本友好UTF-8 带 BOM 编码，记事本打开中文注释不乱码；同时兼容 GBK 保存的文件
写错不崩值写错类型（比如数字写成中文）程序照常启动，用默认值并在启动摘要里用中文提示哪一行错了
改错可恢复问答式配置写入前自动备份原文件为 .env.bak
发布包附带发布目录里有 *配置模板-*.env.example（先看后配）和两个双击式配置 bat

⚠️ 注意：改完 .env 必须重启程序才生效；Docker 版不用 .env 文件，改 docker-compose.yml 或同目录 .env（compose 会自动读取）。

8. 聚宽策略端接入

在聚宽策略里引入 joinquant/jq_signal.py，把下单意图上报给中转服务。要点：

  1. 把 RELAY_URL 改成你的中转服务公网地址。
  2. 把 API_KEY 改成与 RELAY_SIGNAL_KEY 一致的值。
  3. 每个信号必须有全局唯一的 order_id（建议用 策略名+股票+日期+序号），中转服务靠它幂等去重。
# 策略下单处调用（示意）
send_signal(order_id="myStrat-20260911-001",
            security="600519.XSHG", side="buy", amount=100, price=None)
字段必填说明
order_id✅唯一标识，用于幂等去重
security✅聚宽代码，如 600519.XSHG / 000001.XSHE
side✅buy 或 sell
amount✅股数（正整数）
price—委托价；留空/0 时执行端自动取最新价（A 股客户端只支持限价）

9.3 账户查询

四类实时查询：资金、持仓、当日委托、当日成交。查询会下发任务给执行端并向券商客户端实时读取，通常 1～5 秒返回。

查询为空或被弹窗拦截 若同花顺弹出验证码/对话框，可能导致本次读取失败，重试即可；执行端有自动识别与人工兜底机制（见第 11 节）。

9.4 手动下单与撤单

  1. 填写证券代码、方向（买/卖）、数量（股）、价格（可留空=最新价）。
  2. 点「下单」。控制台把任务下发给执行端，同步等待回报后显示委托号与结果。
  3. 撤单：在「当日委托」里找到委托号，填进撤单框点「撤单」。
  4. 一键全撤：点红色「一键全撤」按钮，执行端读取同花顺撤单页后点[全撤]，撤销当日全部可撤委托（已成交/已废单不受影响）。需连续通过两次确认弹窗，请谨慎使用。
证券代码可以只填 6 位数字（{{VER}} 新增） 输入 600519 会自动识别为 600519.XSHG（沪市），000001 → 000001.XSHE（深市）； 带 .SH/.SZ/.SS 等别名后缀也会自动规范化。识别不了的一律拒绝并提示（如北交所 83xxxx、指数 399xxx）， 宁拒不错——绝不猜市场，防下错标的。前端失焦即补全，后端再校验一道。
防重复下单 同一证券+方向+数量在 15 秒内重复提交会被拦截（HTTP 429），避免手抖点两次。

9.5 任务队列

记录每一次操作的执行记录与结果（含状态：pending/running/done/failed/timeout）。排查问题时先看这里。

9.6 用户管理（管理员）

新建用户、改角色、禁用/启用、重置密码、删除。系统强制保留至少一个启用状态的管理员，且不能删除当前登录账号。

9.7 审计日志（管理员）

记录：谁、何时、从哪个 IP、做了什么、结果如何。覆盖登录、登录失败、查询、下单、撤单、用户增删改、权限拒绝等。可按用户名/动作/关键字筛选。

9.8 聚宽信号页（信号追踪）

「聚宽信号」页可查看每一条来自聚宽策略信号的完整生命周期：点击任意一行展开时间线——收到 → 派发 → 执行端回报（accepted / filled / failed），每一步都有时间戳与详情。支持按状态、证券代码、日期筛选与分页。

  • 来源 IP：列表直接显示信号上报来源，便于发现未授权上报。
  • 被拒请求：页面下方单独列出因密钥错误(401)、参数错误(400)、执行端离线(503)被拒绝的请求及原因。
  • 排障路径：策略说"已上报"但没成交 → 先到本页找 order_id；有时间线但没回报=执行端问题，没收到=网络/密钥问题。

9.9 执行端在线状态与「重启同花顺」（{{VER}} 强化）

执行端在线 ≠ 同花顺就绪。从 {{VER}} 起，执行端进程只要活着就向控制台报在线——即使同花顺没启动/没登录/连不上； 心跳会带上券商状态（如 executor-ths[L0]（同花顺未就绪）），概览页一眼能看出"在线但券商没连上"。

「重启同花顺」按钮（查询页旁，需管理员+二次确认）语义：同花顺在运行则安全重启、没运行则直接启动，启动后等待其自动登录并重连（最多 120 秒）。这是同花顺假死/没启动时的唯一远程自救手段，券商离线时也随时可用。

失败熔断（L0~L3）：执行端对连续失败自动降级，防带病重试：

等级触发（120 秒窗口内）行为恢复
L0 正常—正常交易—
L1 退避≥3 次失败拉大轮询间隔成功后自动降回
L2 暂停≥6 次失败暂停自动下单成功后自动降回
L3 熔断≥12 次失败完全停止交易管理员点「解除熔断」或重启执行端

心跳名会带上当前熔断等级（如 executor-ths[L2]）；「用户管理」区有解除熔断按钮（管理员）。

9.10 持仓对账（聚宽 vs 券商，{{VER}}）

「账户查询」页底部有持仓对账卡片，用来回答一个关键问题：聚宽策略以为的持仓，和券商账户的真实持仓，是否一致？

工作方式：

  • 聚宽侧快照：在策略里加两行（配合 jq_signal.py）—— 
    def after_market_close(context):
    report_positions(context)
    收盘后自动把策略持仓快照上报给中转服务。
  • 券商侧持仓：对账时中转服务通过任务队列让执行端实时读取券商客户端持仓（执行端无需升级）。
  • 比对：按 6 位代码全量比对，输出「聚宽持仓 / 券商持仓 / 差额」明细；完全一致显示绿色"持仓一致"。

自动对账：每个交易日 15:05（可用 RELAY_RECONCILE_AT 修改，RELAY_RECONCILE_AUTO=0 关闭）自动执行一次；也可以点「立即对账」随时手动触发（需要交易员权限，执行端在线时约 10~40 秒）。

对账结果的几种状态 持仓一致 / 发现差异（有明细表）/ 无聚宽快照（策略还没配 after_market_close）/ 执行端离线 / 券商持仓为空（可能被弹窗拦截）。 自动对账在法定节假日也会运行，属正常现象（读到的就是当天真实持仓）。
发现差异怎么办 差异只提醒、不自动改仓。常见原因：部分成交、废单、同花顺弹窗导致下单失败、人工在券商客户端手动操作过。请先看「聚宽信号」页时间线定位是哪笔信号出了问题，再人工处理。

10. 风控机制

所有下单（聚宽信号 + 控制台手工）都经过 executor/risk.py，任一项不通过即拒绝并回报原因：

检查项参数（executor/config.py）默认
代码白名单CODE_WHITELIST空=不限制
单笔最大股数MAX_SINGLE_AMOUNT10000
当日累计上限MAX_DAILY_AMOUNT50000
价格偏差MAX_PRICE_DEVIATION3%
卖出持仓校验自动查询实际持仓持仓不足即拒
实盘前务必按自己的资金规模调整阈值 默认值偏保守。放宽容错意味着放大风险，请谨慎设置。

11. 同花顺验证码处理

同花顺会检测频繁自动操作并弹验证码窗口（反机器人机制，无法根除）。本系统用三级降级把影响降到最低：

1
自动识别（主力）：ddddocr 深度学习 OCR 识别验证码 → 自动填入 → 回车，最多重试 5 轮。
2
人工兜底：连续失败时蜂鸣报警 3 声 + 存图 captcha_last.png，90 秒内人工输入也认，检测到填好会自动回车。
3
最后手段：点取消关闭弹窗，操作如实报 failed，绝不带病重试。

每处理一次验证码，执行端自动降频 120 秒，减少再次触发。可单独自测：python executor/captcha.py（只检测弹窗，不做任何交易）。

问题原因 / 解决
双击 exe 窗口一闪就没在 cmd 里运行看报错。最常见是 5010 端口被占用：netstat -ano | findstr 5010
控制台提示执行端离线执行端没启动，或执行端 EXECUTOR_RELAY_URL 指向不对，或 EXECUTOR_API_KEY 与中转 RELAY_EXECUTOR_KEY 不一致。
聚宽上报信号返回 401聚宽端 API_KEY 与中转 RELAY_SIGNAL_KEY 不一致。
查询不到账户/持仓同花顺弹窗拦截读取，重试；或客户端未登录。
升级后页面还是旧样子99% 是浏览器缓存，Ctrl+F5 强制刷新。Docker 强刷无效说明镜像没重建，需 up -d --build。
Docker 只执行 up -d 不生效源码改了必须 build 再 up -d。
忘了控制台管理员密码停服务，备份后删 relay_data.db（或只删 users 表）再重启，会按配置重建默认管理员。
exe 被杀软拦截/报毒PyInstaller 单文件常见误报，加入白名单；或改用源码方式运行。
同花顺下单偶发失败客户端弹窗/升级导致控件失效；锁版本、关自动升级。失败会自动回报 failed，连续失败会触发执行端熔断降级（见 9.9 节）。
同花顺窗口在但内容空白/点了没反应（假死）到控制台点「重启同花顺」（在运行则重启、没运行则启动，全程远程）。执行端已杜绝"误关同花顺窗口"这类自伤行为；真死机时连接会被拒绝并提示重启，不会带病重试。
控制台显示执行端在线，但查询/下单提示"可在本页点重启同花顺恢复"这是 {{VER}} 起的正常语义：执行端在线 ≠ 同花顺就绪。按提示点「重启同花顺」等它自动登录即可，无需到现场。
同花顺为什么突然没了/自动退出多为同花顺自动升级在替换主程序（updater 进程）。建议盘前手动升级到最新、关闭自动升级；执行端发现未运行会在下轮自动拉起。
手动下单填 6 位代码提示"无法识别市场"北交所(4/8/92 开头)、指数(399 等)等不支持自动补后缀，属宁拒不错设计；确需交易请在代码后手动写全 .XSHG/.XSHE 之外的完整标识或先确认标的。
执行端 exe 启动报缺模块用 EXECUTOR_SELFCHECK=1 自检；若缺模型文件，请用官方发布的 exe 而非自行打包。
打开控制台只看到「授权激活」页正式版必须先激活：把页面上 8 位「本机授权账号」发给管理员换卡密，粘贴激活后自动进入控制台（见 5.4 节）。
授权服务器临时连不上还能用吗能。凭本地缓存进入 72 小时离线宽限期（顶栏橙色提示），宽限期内一切正常；超时才拦截。
Docker 激活后重启又要重新激活容器内 /etc/machine-id 重建会变导致授权账号变。按 6.1 节提示挂载宿主机 machine-id 后再激活。
设置 RELAY_LICENSE_ENABLED=0 没跳过授权正式版内置 release.lock，该开关被锁死（防绕过授权）；仅源码开发环境允许关闭。
